# 2026-08-29-permission-tri-card

## Why

用户困惑："里面已授权了，外面点悬浮球还弹 Start recording？"——根因是权限卡片只展示了 2 个权限（悬浮窗/通知），而点球触发的**屏幕录制（MediaProjection）**是第三个独立授权，用户自然以为"已授权"没生效。配合 a11y-screenshot change（无障碍截屏成为主路径），权限卡片应如实呈现**三个能力**各自的开关与说明：悬浮窗、通知、无障碍（截屏）。

## What Changes

- `PermissionCard` 重构为三行：
  1. 悬浮窗权限（现状逻辑不变）
  2. 通知权限（现状逻辑不变）
  3. **无障碍权限（免弹窗截屏）**：状态实时读系统（AccessibilityHelper），已开启=✓绿色"已开启"；未开启=「去开启」直跳系统无障碍设置；行尾说明"开启后点悬浮球零弹窗识读"
- 「屏幕录制」不再作为卡片行（它是 API<30 兜底路径的系统弹窗，不可豁免也无状态可查）；在无障碍行 description 兜底说明"Android 10 及以下使用时由系统弹窗授权"
- README 权限说明表同步三权限
- 被否选项：把屏幕录制列为第四行带状态（进程内投影状态易变，展示会误导）

## 成功标准

- 卡片如实呈现三权限；无障碍行状态与系统设置一致；未开启时「去开启」可直达系统页
- 点悬浮球的授权困惑消除（卡片 + 行说明讲清三者关系）

## 优先级

- P2：与 a11y-screenshot 配对交付（同一批合并）。
